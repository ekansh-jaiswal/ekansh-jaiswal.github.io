## Solution :

This level's a quick one — turns out the password isn't hidden in a commit or a branch this time, but in a **tag**.

A tag is basically a permanent bookmark pointing at a specific commit, and it lives in git's metadata rather than as an actual file in the working directory — so `ls`, `cat`, and even `git log` won't show it to you. The only way to find it is to explicitly ask git for its tags with `git tag`.

Running that here turns up a tag simply called `secret`. From there, `git show secret` dumps out whatever's attached to that tag — and in this case, that's just the password sitting right there as the tag's message.

> Good reminder that git is more of a database with various "pointers" (commits, branches, tags, refs) than just a folder of files — anything checked into one of these can hold data, even if it never shows up as a file you can `cat`.
