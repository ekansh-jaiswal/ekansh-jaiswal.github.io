## Solution :

This level is basically a continuation of Bandit14, except this time the port expects an SSL/TLS connection instead of a plain TCP one — so plain `nc` won't cut it here, we need something that can handle the SSL handshake.

1. Option 1 — using `ncat` with SSL :

```bash
echo "8xCjnmgoKbGLhHFAZlGE5Tmu4M2tKJQo" | ncat --ssl localhost 30001
```

> `--ssl` : tells ncat to wrap the connection in TLS/SSL before sending the data, since the daemon on this port expects an encrypted connection rather than raw TCP.

2. Option 2 — using `socat` :

```bash
socat - OPENSSL:localhost:30001,verify=0

```

> `OPENSSL:localhost:30001` : connects via an OpenSSL-wrapped socket instead of plain TCP.

> `verify=0` : skips certificate verification, since the server is using a self-signed cert which would otherwise cause the handshake to fail.

3. Option 3 — using `openssl s_client` :

```bash 
openssl s_client -connect localhost:30001 -quiet

```

> `-connect host:port` : opens an SSL/TLS connection to the given host and port directly.

> `-quiet` : suppresses extra session info so we mainly see the actual exchange.

The "self-signed certificate" warnings here are expected — the server uses a default "SnakeOil" test certificate, so verification fails but the connection goes through anyway, and we get the password for bandit16 regardless.
