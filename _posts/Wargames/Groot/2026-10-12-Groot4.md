## Objective :

The password for groot5 is the name of the Drax subkey within the HKEY_CURRENT_USER (HKCU) registry hive.

## Solution :

We need to get the `Drax` subkey name rom the HKCU registry hive. 
From out previous encounters with such level, we know we can CD into the Hive and then recursively search for the required name . 

But I was confused, How can someone directly CD into a Registry Hive at the first place? Because from my knowledge. Generally In Windows (10/11 and more) 
we would always use a program known as a "Registry Editor" or `regedit.exe` which would allow us to modify Registry Values. 
So how can we just cd into a registry? I asked this question to Gemini and here's what I found : 

```text 
What is exactly happening here?
You are experiencing a core feature of PowerShell called PSProviders (PowerShell Providers).

In older command-line tools (like cmd.exe), the file system (files and folders) and the Registry were treated as completely different worlds. You used cd and dir for files, and completely different, complex commands (like reg query) for the registry.

PowerShell fixes this by using "Providers." A Provider translates complex data stores into virtual hard drives (PSDrives). Because of this, PowerShell treats the Registry exactly like a file system:

Hives (HKEYCURRENTUSER, HKEYLOCALMACHINE) become Drives (HKCU:\, HKLM:\).

Registry Keys become Folders.

Registry Values become Files (technically Properties) inside those folders.
```

With this knowledge now we can continue searching inside the Registry Hive of HKCU as follows : 

```powershell
PS HKCU:\> gci -filter "Drax" -recurse
```

Here the previous command didn't work since the `-Filter` method is only applicable for File Type System and not the Registry ones. 
Hence the password for the next level is : `destroyer`
