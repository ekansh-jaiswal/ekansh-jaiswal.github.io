For some very odd reason , our previous methods fails to work on such scenarios. Let's investigate as to why is this happening. 
So if we notice properly , we did a basic mistake. We were supposed to print the letters not the word. 
i.e. if we try to count the number of elements as words and as letters we would notice the difference easily as follows : 

```powershell

PS C:\users\Groot2\desktop> ($text -split '').Count

```

Hence when we tried to access the letters , we went out of bound of the array. Hence we got NULL outputs. 
So now if we properly access the letters from 1,481,110 to 1,481,117 we get the following : 


Wait, this is not the right password. we definetly got something wrong. But I don't get it. 
Let's ask Gemini and try to understand what the correct answer should be, and why my solutions were wrong : 

```text
1. The more Command (Why it threw an error)
When you run text = more .\elements.txt (or standard Get-Content), PowerShell reads the file line-by-line and creates an Array. If the file has 5,000 lines, text becomes a list containing 5,000 separate items.

When you called .Substring(1481110, 8), PowerShell looked at the first item in that list (line 1) and tried to extract 1.4 million characters from it. Since line 1 wasn't that long, it threw an "ArgumentOutOfRangeException".

2. The -split Commands (Why it was slow and returned null)
When you used -split '\s+', you told PowerShell to chop the file up by spaces. It created a massive array of individual words.

When you asked for [1481110], PowerShell counted down to the 1,481,111th word in that list. Because the file didn't have that many words, PowerShell silently returned null.

When you used -split '' to split by characters, PowerShell had to create over 2.3 million individual, microscopic objects in your computer's memory. This is highly inefficient, which is why the command took a noticeable amount of time to execute.

3. Get-Content -Raw and .Substring() (Why it worked instantly)
By adding the -Raw flag, you instructed PowerShell to ignore lines, spaces, and formatting entirely. It inhaled the 2.3 MB file and stored it as one single, unbroken String object.

Because text was now just one giant word, .Substring(1481110, 8) didn't have to build arrays or count list items. It mathematically jumped straight to that exact byte in memory and instantly sliced out the 8 characters you needed.
```

And the correct answer is as follows : 

```powershell
PS C:\users\Groot2\desktop> $text = Get-Content .\elements.txt -Raw                                                                                                                         
PS C:\users\Groot2\desktop> $text.Substring(1481110, 8)                                                                                                                                     
 hiding                                                                                                                                                                                     
PS C:\users\Groot2\desktop>   
```

Hence the password for the next level is : `hiding`
