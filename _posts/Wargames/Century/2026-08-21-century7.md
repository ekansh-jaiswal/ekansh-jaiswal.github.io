But this doesn't mean I would stop at this, I tried to understand why the command i used didn't work. So i asked my AI friend and here's the response i got : 

```
Why Your Commands Aren't Working
- The Exact Match Trap: When you use -filter "README", PowerShell is looking for a file named exactly "README" with absolutely no file extension. If the file is named readme.txt, readme.md, or README_flag, it will be completely ignored.
- The Missing Combo: You correctly tried to account for extensions with -filter "README.*", but on that specific execution, you forgot to include the -recurse flag. Therefore, it only searched the root of C:\Users\century7 and didn't check any subdirectories.
- Case Sensitivity: PowerShell is case-insensitive by default. Changing "README" to "readme" in your last command didn't change the behavior; it was still looking for an exact match with no extension.
- The CTF Twist (Hidden Files): By default, Get-ChildItem (gci) does not display hidden or system files. In CTF environments, target files are almost always hidden.

The Corrections You Need
- To fix your current gci approach, you need to combine a few concepts into a single command:
- Use Wildcards Everywhere: Wrap your search term in asterisks so it catches prefixes, suffixes, and extensions (e.g., *readme*).
- Force the Issue: Use the -Force parameter. This tells PowerShell to include hidden and system files in its search results.
- Silence the Noise: When you recurse through user directories in Windows, you will inevitably hit "Access Denied" errors on hidden system junction points (like Application Data). This will flood your screen with red text. Append -ErrorAction SilentlyContinue (or -ea 0 for short) to hide those errors and only see successful hits.
```

So now i know what the `-recurse` flag does and the mistake and the corrections i need to make, so i ran the command : 

```powershell
PS C:\Users\century7\Downloads> gci -Path C:\Users\century7 -Filter "*readme*" -Recurse -Force -ErrorAction SilentlyContinue
```
